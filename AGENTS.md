# AGENTS.md

This file provides guidance to Codex (Codex.ai/code) when working with code in this repository.

## Vision

**pinkha** — a personal note-taking app combining the beauty and fluidity of Craft with the structure of Notion (databases). Full Rust core. Goal: open-source publication, as a rich text editor in Rust does not yet exist in the ecosystem.

Target platforms: iPhone, iPad, Mac. UI decision: **SwiftUI + UniFFI** — 100% native rendering (iOS 26, native scroll physics, native tab bar), Rust for the core.

## Architecture (Clean Architecture)

The repo is a **Cargo workspace** with two crates:
- `crates/chaqaq` — standalone open-source crate published on crates.io (MIT OR Apache-2.0)
- `.` (pinkha) — full application, depends on chaqaq via `{ path = "crates/chaqaq" }`

Dependency rule: `infrastructure` → `application` → `domain`. The domain knows nothing about storage.

### `crates/chaqaq` — standalone crate (published on crates.io)

All inline editing logic lives here. Only dependency: `serde`.

- **`InlineStyle`**: Bold, Italic, Underline, Strikethrough, Color(String), Link(String)
- **`InlineText { content, styles }`** — serializable rich text fragment
- **`RichText`**: flat char string + `Vec<Span>`. Unicode char indices (not bytes). `insert_char` / `delete_char` / `toggle_style` / `restore_spans`. Lossless `From<&Vec<InlineText>>` ↔ `From<&RichText> for Vec<InlineText>` conversion.
- **`EditorState { text, cursor, selection }`**: `insert`, `delete_before/after`, `move_left/right`, `go_to_start/end`, `select(range)`, `toggle_style(style)`
- **`Command` trait** + `Insert`, `Delete`, `ApplyStyle` — each implements `execute` / `undo`
- **`History`**: undo/redo stack, configurable capacity (default 1,000), `apply` / `undo` / `redo` / `can_undo` / `can_redo`
- **`parse_inline(input)`**: state machine over `chars().peekable()`. `**bold**`, `_italic_`, `__underline__`, `~~strike~~`, `{color:text}`, `[label](url)`, combinations.

> **Language note**: doc comments in `crates/chaqaq` are in **English** (open-source crate, international audience) — exception to the "comments in French" rule that applies to pinkha only.

> **Publishing**: bump the version in `crates/chaqaq/Cargo.toml` (semver), then `cd crates/chaqaq && cargo publish`. A published version is immutable. pinkha references chaqaq via `{ path = "crates/chaqaq" }` so it always compiles locally without publishing.

### `domain/document.rs`
Re-exports `InlineStyle` and `InlineText` from chaqaq. Defines pinkha-specific types:
- `BlockContent`: Text, Heading { level, text }, Quote { icon, text }, Todo { done, text }, Divider, Breadcrumb, Database { id }
- `Block { id: Uuid, content: BlockContent, children: Vec<Block> }` — recursive node
- `Document { id, cover, title: Vec<InlineText>, blocks: Vec<Block> }`
- `DocumentMeta { id, cover, title, updated_at }` — lightweight view without blocks for `list()`. `updated_at` populated by SQLite, empty otherwise (`#[serde(default)]`)

### `domain/parser.rs` / `rich_text.rs` / `editor.rs` / `commandes.rs`
Simple re-exports from `chaqaq` — no own logic.

### `domain/database.rs`
Notion-like engine (defined in pinkha, not in chaqaq):
- `PropertyType`: Title, Text, Number, Selection, SelectionMultiple, Date, Checkbox, Url, Relation, Rollup
- `PropertyValue`: corresponding values + `Empty`
- `Entry { id, created_at: String (ISO 8601), values: HashMap<Uuid, PropertyValue> }`
- `ViewType`: Table, Kanban { group_by }, Calendar { property_id }, Gallery
- `Filter { property_id, condition: FilterCondition }`, `Sort { property_id, order, source: SortSource }`
- `SortSource`: Property | Creation | ManualThenCreation (for mixed journals)
- `Database { id, title, properties, entries, views }`, `DatabaseMeta { id, title, updated_at }`

### `application/error.rs`
`PinkhaError`: `NotFound(Uuid)`, `InvalidOperation(String)`, `Io(std::io::Error)`, `Json(serde_json::Error)`, `Db(String)`
— `Db(String)` converts rusqlite errors to string to avoid coupling the application to SQLite.
— implements `std::error::Error` + `From<io::Error>` + `From<serde_json::Error>`

### `application/use_cases.rs`
- `create_document`, `get_document`, `list_documents`, `delete_document`
- `update_document_title`, `update_document_cover`
- `add_block`, `update_block`, `delete_block`
- `reorder_blocks(doc_id, order)` — reorders root blocks
- `reorder_child_blocks(doc_id, parent_id, order)` — reorders children of a block
- `add_child_block(doc_id, parent_id, content)` — nests a block
- `move_block(doc_id, block_id, new_parent_id: Option<Uuid>)` — moves to a parent (None = root)
- `save_edited_block(doc_id, block_id, &EditorState)` — editor → persistence bridge
- `search_documents(query)` — case-insensitive in titles
- `search_in_blocks(query)` — full-text in block content (recursive)

### `application/database_use_cases.rs`
- `create_database`, `get_database`, `list_databases`, `delete_database`
- `add_entry`, `update_entry`, `delete_entry`
- `add_property`, `rename_property`, `delete_property` (cleans up values in entries)
- `add_view`, `update_view(view_id, filters, sorts)`, `delete_view` (blocks on the last one)
- `query(db_id, view_id)` — filters + sorts
- `query_with_rollups` — query + rollups computed at read time
- `column_aggregate(db_id, prop_id, aggregate)`
- `grouped_query(db_id, view_id, group_by)`
- `search_entries(db_id, query)` — case-insensitive across all text values
- `evaluate_rollups(db, entries)` — computes Rollup columns (not persisted)

### `infrastructure/migrations.rs`
Versioned migrations via `rusqlite_migration`. Two functions: `apply_document_migrations` and `apply_database_migrations`. Each schema change = one more `M::up()`.

### `infrastructure/sqlite_document_store.rs` + `sqlite_database_store.rs`
Local-first SQLite storage. Schema: document-as-JSON in a `data` column, with indexed columns (`title_text`, `title_json`, `cover`) for fast `list()` without deserializing blocks.
- `updated_at` managed automatically on every `save()` — ready for future sync
- Soft delete: `delete()` sets `deleted_at` instead of removing — data recoverable for CRDT
- Bundled SQLite (`features = ["bundled"]`) — no system dependency, works on iOS/Android/macOS
- `PRAGMA journal_mode=WAL` enabled for better concurrent performance
- `in_memory()` constructor for tests

### `infrastructure/json_store.rs`
`JsonStore { dir: PathBuf }` — kept for compatibility and existing tests.
`#[serde(alias = "style")]` on `styles` for backward compatibility with old files.

### `ffi.rs` + `pinkha.udl` — UniFFI layer
Public facade exposed to Swift via UniFFI 0.31.
- FFI `PinkhaError`: enum `NotFound { id }`, `InvalidOperation { detail }`, `Storage { detail }` — becomes a native Swift `enum`
- `DocumentMetaFfi` / `DatabaseMetaFfi`: dictionary structs (id, title_plain, title_json, cover, updated_at, created_at)
- `PinkhaApi`: opens both SQLite stores at the same path, exposes all document and database operations
- Blocks and full databases transit as JSON (String) to avoid the recursive `Block` type in the UDL — Swift decodes via `Codable`
- `add_block` returns the created block's UUID (not the entire document)
- Shift+Enter handled on the editor side: `EditorState.insert('\n')` + `save_edited_block` — no `LineBreak` variant needed in the model

Swift usage:
```swift
let api = try PinkhaApi(dbPath: path)
let id  = try api.createDocument(title: "My note")
let json = try api.getDocumentJson(id: id)  // → Codable
```

### `app/Sources/` — SwiftUI UI Layer

**`Models.swift`** — Swift mirrors of Rust types serialized by serde:
- `DocumentFfi`, `BlockFfi`, `InlineTextFfi`, `InlineStyleFfi`, `BlockContentFfi` — all `Codable`
- `InlineStyleFfi` / `BlockContentFfi`: enums with custom `init(from:)` / `encode(to:)` for serde's externally-tagged format
- Helpers on `BlockContentFfi`: `plainText`, `spansOrEmpty`, `isTodo`, `isTodoDone`, `withText`, `withSpans`, `toAttributedString`

**`RichTextEditor.swift`** — rich text editor:
- `ExpandingTextView : UITextView` — auto height via `intrinsicContentSize`, hooks for Shift+Enter and bold/italic/underline toggles (hardware keyboard)
- `RichTextEditor : UIViewRepresentable` — `spans` / `isFocused` bindings, `onSave`, `onSaveSpans`, `onNewBlock`, `onDeleteBloc`, `onMergeAvecPrecedent`, `onConvert`, `onUndo`/`onRedo` callbacks + live closures `canUndoProvider`/`canRedoProvider`
- `spansToAttributed` / `attributedToSpans` — bidirectional conversion with custom `.pinkhaColor` key for reliable color name round-trip
- `NSAttributedString.Key.pinkhaColor` — custom attribute for storing the color name (reliable round-trip)
- `MenuButton : UIButton` — overrides `contextMenuInteraction(_:willEndFor:)` to detect dropdown menu close (hide-on-menu, Notes.app style)
- Toolbar pill (Notes.app style) — custom `UIView` with `UIVisualEffectView(UIGlassEffect())`, horizontal `UIScrollView`, order: Paste / Aa (B/I/U/S via dropdown) / Highlighter (palette via menu) / Undo / Redo / Return / Dismiss keyboard
- Hide-on-menu: opening a dropdown via `UIDeferredMenuElement.uncached` hides the pill; `MenuButton.onMenuWillEnd` restores it on close (covers dismiss by tapping outside)
- `fontWithTraits(_:bold:italic:)` — bold/italic with `boldSystemFont`/`italicSystemFont` fallback (SF Pro doesn't always propagate `withSymbolicTraits`)
- `markdownShortcut(for:)` (free function, testable): `# ` → H1, `## ` → H2, `### ` → H3, `> ` → Quote, `!! ` → Callout, `[ ] ` → Todo, `---` → Divider
- Optimization: `lastSyncedSpans` per Coordinator — skips `spansToAttributed` recomputation when another block receives the keystroke (SwiftUI global re-render but this block hasn't changed)
- Optimization: `lastCanUndo`/`lastCanRedo` — avoids recreating `UIImage` on every keystroke for undo/redo toolbar buttons
- `toolbarLineBreak()`: inserts `\n` via `tv.insertText` + defensive `shiftEnterTyped = false` reset after (programmatic insertText can bypass `shouldChangeTextIn`)
- `textViewDidChange` calls `save()` on every keystroke → burst undo anchor captured on the VM side. SQLite persist is deferred to the burst flush (1 write per burst, not per character)

**`ContentView.swift`** — 3-tab root + store:
- `PinkhaStore : ObservableObject` — `PinkhaApi`, document CRUD, `search(query:)` → `api.searchDocuments`
- `ContentView` = `TabView { Tab("Notes") Tab("Databases") Tab("Search") }` iOS 26
- `NotesHomeView`: greeting, `RecentStrip` horizontal strip (5 most recent docs, `RecentCard` 150×140 pt), `List` sections with swipe-to-delete, FAB `square.and.pencil`
- `DatabasesHomeView`: placeholder (full backend exists, UI coming)
- `SearchView`: SwiftUI `.searchable` + real-time results via `store.search(query:)`
- `SectionHeader`: uppercase label `.caption.weight(.semibold)` with kerning

**`DocumentView.swift`** — document editor:
- `EditableBlock : Identifiable, Equatable` — in-memory model: `id`, `content: BlockContentFfi`, `spans: [InlineTextFfi]`, `done: Bool`
- `DocumentViewModel : ObservableObject, @MainActor` — `load`, `saveBlock` / `saveBlock(id:spans:)` (burst), `persistBlock` (structural mutations), `addBlock`, `deleteBlock` / `deleteBlocks(ids:)`, `moveBlock`, `applyBlockOrder`, `toggleBlockDone`, `updateBlockIcon`, `convertBlockContent`, `saveTitle`, `saveCover`
- Direct in-memory mutations (no SQLite reload after insert/delete — avoids clearing content being typed during a SQLite reload). Memory/disk desync is detected on next load.
- Supported blocks: Text, Heading (1/2/3), Quote, Callout (Quote with emoji icon), Todo, Divider
- `ForEach($vm.blocks) { $block in }` — two-way binding for in-place editing
- Native drag & drop via `.onMove` + `EditMode`
- Swipe-to-delete + context menu
- `.scrollDismissesKeyboard(.interactively)` — native swipe keyboard dismiss
- `autoFocusId` — automatic focus on newly created OR reinserted block (undo of a deletion)

**Undo / redo (Swift):**
- Native `UndoManager`, `levelsOfUndo = 1000` (aligned with the Rust backend's default)
- 2 synchronized UIs: glass pill bottom-left (keyboard closed) + buttons in keyboard toolbar (keyboard open)
- `canUndoProvider`/`canRedoProvider` = live closures that read `vm.canUndo`/`vm.canRedo` → always fresh on every updateUIView / textViewDidChange / didChangeSelection
- `vm.canUndo = undoMgr.canUndo || !blockBurstAnchor.isEmpty` — the button also lights up when a typing burst is pending (undo flushes first then undoes)
- All VM ops register their inverse: add/delete/move block, toggle todo, change icon, convert content, save title, save cover, typing
- **Burst undo for typing** (Notes style): a continuous burst of `saveBlock` on the same block = 1 undo step. `burstInterval = 300 ms` of inactivity → flush + SQLite persist + register undo. Block switch flushes the previous burst immediately.
- `BlockSnapshot { content, spans, done }` (Equatable) — state captured pre-burst (`blockBurstAnchor`) or stable (`blockSnapshots`)
- `applyBlockSnapshot(blockId:snapshot:)` replaces the entire element in `blocks` (reliably triggers `@Published`) + persists + re-registers the reverse
- `NSUndoManagerCheckpoint` observer async-dispatched for `objectWillChange.send()` — avoids "Publishing changes from within view updates" warning

**`Resilience.swift`** — error UX:
- `PinkhaError.userMessage` (EN), `isRecoverable`, `tryCatch(into: &errorMessage)`, `.errorAlert(message:onRetry:)`

## Git workflow

### Permanent branches
- `master` — production. Everything here must be stable, tested, releasable.
- `staging` — pre-prod / QA. Promoted from `dev` when a batch of features is ready to test.
- `dev` — integration. All features/fixes are merged here before promotion.

### Ephemeral branches (create then delete after merge)
- `feature/<short-name>` — new feature
- `fix/<short-name>` — bug fix
- `refactor/<short-name>` — refactoring without behavior change
- `docs/<short-name>` — documentation-only changes
- `chore/<short-name>` — maintenance (deps, CI, tooling…)
- `perf/<short-name>` — targeted performance optimization

### Flow
1. `git checkout dev && git pull` then `git checkout -b feature/my-feature`
2. Commits on the branch, PR to `dev`
3. Merge into `dev` → ephemeral branch is deleted (remote + local)
4. When `dev` is stable: merge `dev` → `staging` for QA
5. When `staging` is validated: merge `staging` → `master` (= release)

### Rules
- **Never commit directly to master, staging, or dev** — always via PR from an ephemeral branch.
- **kebab-case naming**: `feature/undo-redo-toolbar`, not `feature/UndoRedo` nor `feature/undo_redo`.
- **One branch = one intent**: do not mix feature + fix + refactor in the same branch.
- **Delete merged branches** (remote AND local) — avoid accumulation.

## Code style

### Language
- **Code in English**: all identifiers (types, functions, variables, fields, parameters, FFI methods) in idiomatic English. No French identifiers.
- **Comments in French**: all comments, doc-comments and inline explanations in `pinkha` are in French. **Exception**: `crates/chaqaq` is an open-source crate — its `///` and `//!` are in English (international audience).
- **User-facing strings in English**: `Text("Good morning")`, `placeholder("Document title")`, `accessibilityLabel("Cancel")` — visible to the English-speaking end user.

### Conventions
- No `unwrap()` — always `?` and `Result` on the Rust side
- Idiomatic naming: Rust `snake_case`/`PascalCase`, Swift `camelCase`/`PascalCase`
- `flush()` pattern for parsers

### Architecture — SOLID + Clean Architecture
- **Single Responsibility**: each module/type does one thing. Domain (pure types), application (use cases + traits), infrastructure (storage), ffi (adapter). No "God objects".
- **Open/Closed**: adding a feature = new type/impl, not modifying use cases. Exhaustive `match` statements force the compiler to handle each added variant (intentional).
- **Liskov**: every `DocumentRepository`/`DatabaseRepository` implementation must be strictly substitutable (tests run on `MockRepo`, production on `SqliteDocumentStore`).
- **Interface Segregation**: one trait = one role. `DocumentRepository` and `DatabaseRepository` are separate; a document client does not depend on database methods.
- **Dependency Inversion**: use cases depend on abstractions (`&dyn DocumentRepository`), never on concrete stores. Only `ffi.rs` (composition root) knows the concrete implementations (`SqliteDocumentStore`).

### Resilience (back + front)
- **Typed errors, no panic**: `Result<T, PinkhaError>` on Rust side, throws/Result on Swift side. Never `unwrap()`/`!` in production.
- **Error conversion at boundaries**: `From<E>` Rust (cf. `From<CoreError> for PinkhaError` FFI); mapping to `PinkhaError` on Swift side via `do/catch` that surfaces an `errorMessage: String?` to the store.
- **No coupling to impl**: `PinkhaError::Db(String)` converts `rusqlite` errors to string to avoid coupling the application to SQLite.
- **Retry with exponential backoff**: `application/resilience.rs::retry_with_backoff` (3 attempts, 50ms→500ms doubled) wraps SQLite write/read operations. `is_transient()` only retries lock/blocking-I/O errors, never business errors (`NotFound`, `InvalidOperation`).
- **FFI boundary validation** (`ffi.rs`):
  - `parse_uuid` rejects malformed UUIDs as `InvalidOperation`
  - `parse_json` refuses payloads > **5 MB** (`MAX_JSON_BYTES`)
  - `check_string` refuses strings > **64 KB** (`MAX_STRING_BYTES`) — applied to title/query/new_name
- **Soft delete + `updated_at`**: no hard deletion, CRDT/sync preparation. Every write goes through `save()` which updates `updated_at`.
- **Optimistic UI mutations**: memory first (blocks in memory), persistence after — avoids clearing content being typed during a SQLite reload. Memory/disk desync is detected on reload.
- **Concurrency**: SQLite in `WAL` for concurrent reads. `@MainActor` on Swift side for view models. No direct store access outside the facade.
- **Swift error UX** (`Resilience.swift`):
  - `PinkhaError.userMessage` → user-readable English message (instead of the raw error)
  - `PinkhaError.isRecoverable` → true for `Storage` (retry possible)
  - `tryCatch(into: &errorMessage)` captures the error without propagating, surfaces the message to the view model
  - `.errorAlert(message:onRetry:)` SwiftUI modifier that presents an alert with an optional "Retry" button
- **3-level tests on Rust side**: unit (`#[cfg(test)] mod tests` in each module — including `resilience.rs` with 6 tests), integration (`tests/integration_*`), E2E (`tests/e2e_*`). 204+ tests.
- **3-level tests on Swift side**: `app/Tests/Unit/` (Swift Testing — `@Suite`/`@Test`/`#expect`, pure code), `app/Tests/Integration/` (Swift ↔ real FFI with temporary SQLite DB), `app/Tests/UI/` (XCUITest — drives the app like a user). xcodegen targets: `PinkhaTests`, `PinkhaIntegrationTests`, `PinkhaUITests`. **186+ Swift tests.**

**Test commands**:
```bash
# Rust only (fast, no simulator):
cargo test

# Full Swift (all levels, requires booted simulator):
xcodebuild test -project app/Pinkha.xcodeproj -scheme Pinkha -destination 'id=<UDID>'

# Swift unit + integration only (fast, no XCUITest):
xcodebuild test -project app/Pinkha.xcodeproj -scheme Pinkha -destination 'id=<UDID>' \
    -only-testing:PinkhaTests -only-testing:PinkhaIntegrationTests

# Swift UI only:

    -only-testing:PinkhaUITests
```

- Block mutations in Swift are done in memory first (no SQLite reload after insert/delete) to avoid clearing content being typed.
- `fontWithTraits(_:bold:italic:)` uses `boldSystemFont`/`italicSystemFont` as fallback because `withSymbolicTraits` returns `nil` for SF Pro in certain iOS contexts.
- `NSAttributedString.Key.pinkhaColor` stores the color name (String) alongside `.foregroundColor` for a reliable `NSAttributedString ↔ [InlineTextFfi]` round-trip.
